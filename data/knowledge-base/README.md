## 三、文件 Metadata 規格

每份文件開頭都有 YAML front matter，RAG 切塊時建議把這些欄位帶進每個 chunk 的 metadata，方便篩選與附出處：

```yaml
doc_id: IT-FAQ-001          # 唯一文件編號，Golden Set 的 source 會引用
title: 帳號、密碼與多因子驗證 FAQ
department: 資訊處／IT 服務台   # 權責單位
category: IT支援             # IT支援｜系統手冊｜人事規章｜行政財務｜業務流程｜專業術語｜教育訓練｜表單｜專案經驗｜公司總覽
doc_type: FAQ               # FAQ｜SOP｜手冊｜辦法｜詞彙表｜教材｜報告｜總覽
version: v3.2
effective_date: 2026-03-01
status: 生效中               # 生效中｜已廢止
owner: 資訊處 服務台科
confidentiality: 內部使用
keywords: [...]
```

文件內的章節以 `##`／`###` 標題分段，Golden Set 的 `source` 以 `doc_id#章節標題` 標示應被檢索到的段落。

## 四、給 RAG 測試用的刻意設計

1. **版本衝突**：`01_IT支援FAQ/IT-FAQ-002-OLD_VPN舊版說明_已廢止.md` 為 `status: 已廢止` 的舊版（舊 VPN 軟體、舊網址）。好的系統應優先引用生效中的 `IT-FAQ-002`，或主動提醒舊版已廢止。
2. **跨文件問題**：部分題目需要結合兩份文件（例如「新人第一天拿筆電」需要新人報到 SOP＋設備 FAQ）。
3. **無答案題**：測試集約 10% 的題目在知識庫中刻意沒有答案，用來測拒答（Abstention）。
4. **口語與錯字變體**：測試集中每題附 `variants`，含口語、錯字、縮寫寫法。
